# Synthetic dataset: Smart Operator Assistant for CAT machinery

Generated by `generate_dataset.py` (seed 42, 2025-05-01 to 2025-05-30, Mon–Sat day shifts 08:00–17:00).
12 machines (10 diesel, 2 electric) across 3 sites, 15 operators. Everything is synthetic; the
`reference_model` column names real CAT model classes only to calibrate fuel burn and productivity.

## Files

| File | Grain | Use it for |
|---|---|---|
| `telemetry_1min.csv` | 1 row per machine per minute | Live dashboard, safety rules, anomaly detection |
| `machine_summary_2h.csv` | 1 row per machine per 2 h | Same columns as the sample dataset (+3 extra) |
| `tasks.csv` | 1 row per task | Daily task dashboard, task time estimation (target: `actual_duration_min`) |
| `machines.csv`, `operators.csv`, `sites.csv` | master data | Admin portal |
| `energy_points.csv`, `energy_events.csv` | fuel bowsers/chargers, refuel & charge sessions | Energy module, EV charging |
| `weather_hourly.csv`, `weather_alerts.csv` | per site per hour / alert windows | Climate module, time estimation features |
| `safety_alerts.csv` | rule-engine output | Baseline alerts (simple thresholds) |
| `anomalies_ground_truth.csv` | planted events | Evaluating your anomaly detection – do NOT use as a model input |
| `training_records.csv` | course completions | Training hub, certification checks |
| `incidents.csv` | operator-reported incidents | Incident log |

## Telemetry columns

`state`: working / idle / travel / off / charging / refueling / weather_hold / heat_rest.
`power_on`: engine (or motor) running. `operator_present`: seat switch. `seatbelt_status`: Fastened / Unfastened.
Diesel machines fill `engine_rpm`, `fuel_level_pct`, `fuel_rate_lph`; electric machines fill `battery_soc_pct`, `power_kw`
(negative while charging). `energy_used` = litres (diesel) or kWh (electric) in that minute.
`proximity_min_m`: nearest detected person/object, 20 = nothing in range; zone danger < 2 m, caution 2–5 m.
`load_cycles`: completed load/dump cycles in the minute. `harsh_events`: abrupt control inputs.
`anomaly_id` / `anomaly_type`: ground-truth label for the minute (blank = normal). Drop these before training.

## Planted anomalies (ground truth)

excessive_idling, unattended_running (engine on, operator out of seat), unbelted_operation, proximity_breach,
overspeed_travel (site limit 10 km/h), harsh_operation, overheating (hot days only), abnormal_fuel_burn
(whole shift, subtle – rules miss it, ML should catch it), fuel_loss (drop while parked at lunch).
Three operators have hidden behaviour profiles (more frequent specific violations) for per-operator analytics.

## Built-in relationships worth exploiting

- Task duration depends on operator skill, ground condition (wet after rain, rocky), rain, heat and fatigue.
  `planned_duration_min` is the admin's naive rule of thumb, so a model has a baseline to beat.
- Heatwave alerts trigger mandatory rest breaks; lightning alerts and heavy rain trigger weather holds.
- Electric machines opportunity-charge at lunch and go to the site charger when SOC < 25 %.
- One operator's seatbelt refresher course has lapsed – links training records to violations.

## Known limitations

- Proximity data is fully assumed (models a radar/UWB-tag system).
- About 24 % of tasks end the day `partial` (carried over); `actual_duration_min` is blank for those.
- Regenerate with a different seed or more days: `python generate_dataset.py --seed 7 --days 60 --out data`
